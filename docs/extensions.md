# F·I 확장 계약

갱신일: 2026-10-21 · 분석기 0.4.0 · 정적 데이터 계약 2.1 유지

## 범위

F는 기존 HTML 보고서에 포함되는 오프라인 관계 탐색기다. I는 별도 `python -m knitcode_analyzer_v2.assist` 명령의 로컬 검색·문맥 구성·선택 API 설명이다. G(VS Code)·H(Git), 임베딩·의미 검색·에이전트 실행·소스 수정은 포함하지 않는다. 기본 분석 명령은 네트워크에 접근하지 않는다.

0.3.0의 별도 `runtime` 명령은 [J 동적 분석 계약](runtime.md)을 따른다. F 그래프에 실행 관측 보기를 추가하지만 I의 AI 문맥은 여전히 정적 결과만 사용한다.

2026-10-16 확장: `runtime --discover`는 이름에 의존하지 않는 정적 후보와 HTML 구조 보고서를 제공한다. `runtime --ai api|ollama`는 같은 어댑터를 사용해 정적·동적 집계 설명을 보고서에 추가한다. 기존 `assist`의 코드 원문 기반 문맥과 별도의 제한된 프로젝트 사실 문맥을 사용하며 원문 전체·실행 인자·로그는 전송하지 않는다. AI가 실행 대상을 고르거나 그래프 관계를 바꾸지는 않는다.

`study`의 통합 계약은 위 `assist` 및 수동 `runtime --ai`와 별개다. `study_context`는 정적 후보·입력 구문·README 일부와 실행 피드백을 제공하며 AI가 제한된 JSON 실행 계획을 선택한다. 실행기가 새 복사본에 입력을 전달하고, 결과에 따라 다음 계획을 요청한다. 최종 안내는 정적 구조·실제 관측·문서 근거를 사용해 디렉터리와 파일 역할·읽기 순서를 설명한다. 계획과 안내는 각각 별도 응답 계약을 검사하고 기존 그래프는 변경하지 않는다. 선택 도구 관측도 근거로 제공한다. 전체 흐름은 [ANALYSIS_FLOW.md](../ANALYSIS_FLOW.md)를 따른다.

## 그래프

- `graph.graph_data`는 정적 결과에서 파일 집계와 정의 관계 집계를 만든다. 반환되는 `file_edges`, `symbol_edges`, `directory_edges`의 각 관계는 원본 `edge_ids` 전체를 보존한다. `directories`는 같은 디렉터리에 직접 들어 있는 파일 ID를 묶은 표시 전용 그룹이다. 실행 가능 패키지라고 추정하지 않으며 정적 nodes에는 추가하지 않는다.
- 기본 화면은 **전체 구조 / 파일 요약**이다. 연결 없는 파일도 포함하며 파일은 폴더별로 배치한다. 파일 요약은 소속 이외의 관계를 파일 단위로 집계하고 같은 파일 관계는 자기 자신을 향한다. 폴더 요약은 이 파일 관계를 다시 집계한다. 각 요약에서 호출·import·변수 읽기/쓰기/삭제·참조·상속·대입식 참조를 필터로 구분한다.
- **호출 흐름**은 선택한 시작점에서 calls/observed_calls의 나가는 연결을 너비 우선으로 탐색한다. 열은 최소 호출 단계이며 실제 실행 순서가 아니다. 정적 annotation/definition_expression 문맥의 호출은 제외한다. 순환·재귀 연결은 유지하며 방문 노드를 다시 큐에 넣지 않는다. 진입점 후보가 있으면 초기 선택에 우선하고 사용자가 다른 시작점을 고를 수 있다.
- **주변 관계 탐색**에서는 함수·클래스·변수 종류와 검색이 선택 목록만 좁히고 이웃은 유지한다. **전체 구조**에서는 검색과 종류 필터가 표시 대상 전체를 좁힌다. 방향과 주변 확장 버튼은 주변 탐색에만 적용한다.
- 대상 ID가 없는 관계는 그래프 edge로 만들지 않고 해당 소스 노드의 상태 목록에 남긴다. 외부 대상이 존재한다고 추정하는 노드는 없다.
- 주변 탐색은 초기 1단계, 방향과 유형 필터, 중심 변경, 주변 확장, 검색, 확대·축소를 제공한다. 모든 모드에 노드 40·관계 묶음 100개 상한과 생략 수를 표시한다. 원본 JSON에는 상한을 적용하지 않는다. Markdown에는 폴더별 전체 파일 구조 Mermaid(파일 40개·파일 간 호출/import 80묶음)를 추가하고 생략 수를 표시한다.
- 정적 JSON 스키마를 변경하지 않는다. 표시 데이터는 HTML 내부의 inert JSON으로 삽입하며 `<`, `>`, `&`를 이스케이프한다. 소스 문자열은 DOM의 `textContent`로 표시한다.
- 실행 스크립트의 SHA-256을 CSP에 지정하고 외부 자원·네트워크를 허용하지 않는다. 그래프 라이브러리·CDN·서버 설치가 필요 없다.
- 코드 위치 이동은 HTML의 기존 근거 앵커까지다. 에디터를 열거나 로컬 소스를 실행하지 않는다.

## 검색과 문맥

`search`는 이름·경로·docstring의 대소문자를 무시한 단어 포함 검색이다. 이름 완전 일치·부분 일치·경로·docstring 순으로 가중하며 동점은 경로·ID로 정렬한다. 반환 상한은 20개이며 무작위 추천이나 AI 호출은 없다.

`context`는 매번 새 정적 분석에서 검색의 첫 결과 또는 명시한 `--node`를 선택한다. 호출·import 관계의 양방향 거리 0~2에서 후보를 찾는다. 거리, 검색 점수, 경로·ID 순으로 우선순위를 정한다. 명시된 소속 관계만으로 같은 파일 전체를 자동 첨부하지 않는다. 선택한 노드 자체가 파일이면 그 파일 범위를 하나의 원문 단위로 취급한다.

기본 예산은 원문 16,000자·8개 노드·거리 1이다. 원문은 정의 범위 전체를 사용하며 예산에 맞추려고 중간을 잘라 위치와 내용을 다르게 만들지 않는다. 초과 노드는 이유와 함께 생략한다. 관련 관계 최대 80개와 초과 수를 기록한다. 원문 밖의 관계 endpoint는 ID만 포함될 수 있으며 해당 원문이 제공되었다는 뜻이 아니다.

소스를 다시 읽을 때 프로젝트 경계·링크·원본 바이트 SHA-256을 확인한다. 선언된 인코딩으로 디코딩하고 AST의 UTF-8 바이트 위치로 원문을 추출한다. CRLF도 보존한다. 읽기 실패·변경된 파일은 오류로 중단하며 다른 시점의 원문을 조용히 섞지 않는다. 모든 파일을 원자적으로 잠그는 스냅샷 기능은 아니다.

문맥 버전 1.0은 snapshot, 분석 상태·옵션·진단 코드, 질문, 대상 ID, 선택 방식, 예산, 근거 ID·파일·범위·해시·원문, 관계, 생략 및 미제공 범위, 입력 해시를 포함한다. `input_hash`는 해당 필드를 제외한 문맥 전체의 정규화 JSON SHA-256이다. 문맥은 모델 토큰 수 예산과 같지 않다.

## 선택 API와 응답

`--provider api`는 외부 또는 로컬 Chat Completions 호환 서버를 사용한다. 모델·주소에는 기본값이 없으며 키는 환경 변수로만 받는다. 참고 계약: [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

`--provider ollama`는 별도 [Ollama 네이티브 Chat API](https://docs.ollama.com/api/chat) 어댑터다. 기본 `http://127.0.0.1:11434/api/chat`에 요청하며 루프백 주소만 허용한다. `format: json`, `stream: false`, `options.num_predict: 4096`, 설정 가능한 `options.num_ctx`(기본 16384)를 사용한다. `done: true`, `done_reason: stop` 응답만 처리한다. 외부 API 환경 변수와 키를 사용하지 않으며 알려진 cloud 모델 태그를 거부한다. 서버의 임의 프록시나 사용자 정의 모델 동작까지 검증하지는 않으므로 로컬 전용 사용에는 다운로드한 모델과 `OLLAMA_NO_CLOUD=1`로 시작한 서버를 사용한다.

- `explain`만 전송하며 질문·선택 원문·상대 경로·정적 관계·분석 범위가 요청에 담긴다. 주소와 모델, 제공 원문 수를 stderr에 표시한다.
- 원격 HTTPS, 루프백 HTTP/HTTPS 지원. HTTP 루프백은 `localhost`, `127.0.0.1`, `::1`로 한정한다. 루프백은 프록시를 우회하고 리디렉션은 모두 거부한다.
- 요청은 최대 1MB, 응답은 최대 2MB, 연결·읽기 timeout은 기본 60초(설정 1~600초)다. timeout은 소켓 작업 제한이며 전체 작업의 엄격한 벽시계 시간 상한은 아니다. 자동 재시도하지 않는다.
- 비스트리밍 JSON 응답이며 `finish_reason=stop`만 완료로 처리한다. 거부·잘린 응답·JSON 오류·없는 근거 ID·없는 제안 노드를 실패로 처리한다.
- `claims`는 observation/inference와 하나 이상의 제공 근거 ID를 포함한다. 근거 위치는 모델이 임의로 쓴 좌표를 신뢰하지 않고 해당 ID의 실제 파일·범위·해시로 연결한다.
- 관계 제안은 별도 `suggested_relations`에 `ai_hypothesis_unverified`로 남긴다. 정적 edges·HTML·manifest를 수정하지 않는다. 근거 위치가 유효해도 설명이나 제안 자체의 의미 정확성을 검증한 것은 아니다.
- 프롬프트는 원문·docstring의 지시를 신뢰하지 않도록 규정하고 도구 실행 기능을 제공하지 않는다. 이를 완전한 프롬프트 주입 방어로 주장하지 않는다.
- 결과에 모델·대상 주소·프롬프트 버전·snapshot·문맥 입력 해시·실제 요청 해시를 남긴다. API 키와 HTTP 오류 본문은 저장하지 않는다.
- 실패는 별도 JSON의 `status: failed`, 오류 설명, 문맥으로 남기며 종료 코드 3이다. 입력·출력 오류 2, 취소 130, 성공 0이다. AI 출력은 새 파일에만 저장한다.
- `--markdown-output`은 같은 설명 응답을 한국어 Markdown으로 추가 저장한다. 질문·상태·모델·해시, 관찰/추정, 근거 원문·위치, 미제공 범위, 실패 이유를 담는다. 모델 문자열은 이스케이프하며 원문 코드 블록은 원문보다 긴 fence를 사용한다. 출력 경로는 전송 전에 충돌을 검사한다. 두 파일 저장 전체가 하나의 원자적 트랜잭션은 아니므로 디스크 오류 시 일부 파일만 저장될 수 있다. `report.html`·정적 manifest에는 포함하지 않는다.

`context` 파일을 검토한 뒤 `explain`할 수 있으나 후자는 그 파일을 재사용하지 않고 재분석한다. 동일 소스·옵션·질문이면 동일 문맥 해시가 생성되고, 원문이 바뀌면 해시도 바뀐다. 실제 제공 서비스와 모델별 품질·비용·처리 한도는 별도 검증이 필요하다.

## 검증 범위

Python 회귀·그래프 근거 보존·스크립트 삽입 경계·문맥 선택/예산/변경 탐지·모의 API 성공/실패를 테스트한다. `tests/graph_ui_smoke.mjs`는 모의 DOM에서 검색·필터·방향·확장·초기화·근거 선택·확대를 실행한다. 실제 브라우저 렌더링·키보드 접근성 전체 검수와 유료 또는 로컬 실모델 호출은 별도이며 수행 여부는 [검증 기록](validation.md)에 명시한다.
